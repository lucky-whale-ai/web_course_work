## Уточнения пользователя — обязательные критерии

1. Главная страница должна совпадать с эталоном при проверке наложением в PerfectPixel. Формулировка «визуально похоже» не является критерием завершения.
2. Подготовить полноценные планшетные макеты шириной 768 px.
3. Адаптировать существующие мобильные макеты с 375 до 320 px. Это перерасчёт ширины контейнеров, переносов и высот, а не пропорциональное уменьшение всего изображения.
4. Сначала завершить макеты и зафиксировать эталоны. Обратный импорт сайта в Figma допускается как вспомогательный инструмент для новых экранов; он не доказывает соответствия исходному макету главной.
5. Планировать девять новых содержательных коммитов. Десятый допускается для обнаруженных в финале ошибок. Регулярность по неделям исключена из плана по указанию пользователя; критерий методички от этого не меняется.

## Проверка главной через PerfectPixel

1. Экспортировать каждый завершённый эталон в PNG при масштабе 1× и сохранить идентификатор фрейма, дату и размер.
2. Подключить исходные файлы шрифтов и изображений. Проверить семейство, начертание, размер, высоту строки, межбуквенный интервал и кадрирование изображений.
3. Зафиксировать состояние: русский язык, светлая тема, стандартный размер текста, первый слайд, закрытые меню и диалоги, одинаковые данные.
4. Открыть Chrome при масштабе 100%. Сверять фактическую ширину области содержимого страницы с шириной PNG; не ориентироваться на внешнюю ширину окна браузера.
5. Дождаться загрузки шрифтов и изображений. Для снимка отключить автоматическую смену слайдов и завершить анимации.
6. Наложить PNG без дополнительного масштабирования. Проверять каждую секцию: геометрию, переносы строк, интервалы, границы, иконки и положение изображений.
7. Сопоставить полную высоту страницы и координаты начала секций: небольшие ошибки высоты текста не должны накапливаться к подвалу.
8. Повторить для 320, 768, 1440 и 1920 px, а затем проверить промежуточные ширины на переполнение и потерю контента.
9. Сохранить доказательства сравнения и список исправленных расхождений. Не объявлять pixel-perfect без фактического сравнения. Разницу сглаживания шрифтов между браузером и Figma отделять от ошибок геометрии и типографики.

## Проверка адаптивных макетов

- Исходные desktop-фреймы сохранить в качестве эталонов.
- Для 320 px использовать мобильную структуру: сохранить читаемый кегль и размеры элементов управления, изменить доступную ширину и дать текстовым блокам увеличиваться по высоте.
- Для 768 px отдельно выбрать колонки, размеры изображений и компоновку секций; не растягивать мобильный экран целиком.
- Проверить шапку, hero, карточки, сертификаты, подвал, формы и открытое меню.
- Сохранить исходные компоненты, стили и изображения; проверить ограничения ширины и Auto Layout.
- Проверить каждую страницу и диалог по отдельности, включая длинные подписи и состояния ошибок.

## Обнаруженная зависимость: исходные шрифты

В главной используются точные Figma-имена:

- `Golos / Text Regular`;
- `Golos / Text Medium`;
- `PT Root UI / Bold`.

При проверке 08.09.2026 вызовы загрузки всех трёх начертаний в инструменте Figma завершились ошибкой отсутствия семейства. Локально в проверенных системных и пользовательских папках шрифтов Windows соответствующие файлы также не найдены по именам.

В инструменте доступен `Golos Text`, но идентичность его версии, метрик и очертаний исходному `Golos` пока не подтверждена. Автоматическая замена не выполнена. Необходимо обеспечить доступ к исходным шрифтам в среде редактирования Figma и использовать те же версии в браузере. Наличие файлов на компьютере само по себе ещё не подтверждает их доступность облачному инструменту Figma.

Статус: выполнены чтение и измерение макетов, проверка шрифтов и уточнение плана. Макеты 768/320 и вёрстка ещё не созданы; проверка PerfectPixel ещё не выполнялась.

## Девять этапов реализации

1. `init: set up coursework project` — ТЗ, карта сайта, роли, структура проекта, сборка, JSON Server, пробное чтение и запись API, решение по размещению API, каркас записки.
2. `docs: add design specifications and assets` — доступность исходных шрифтов, адаптивные макеты 768/320, дополнительные экраны, вайрфреймы, UI-kit, мудборд, экспорт эталонов. Первый приоритет — главная.
3. `feat: add shared interface and preferences` — сетка, типографика, общие компоненты, burger menu, словари, темы, доступность, сохранение и сброс настроек.
4. `feat: implement public company pages` — главная с проверкой наложением, информационные страницы, карта, карусель минимум из шести изображений, модальные окна и уведомления.
5. `feat: add project catalog and data browsing` — API каталога, карточки, детальная страница, поиск, фильтр, сортировка, пагинация, загрузка и обработка ошибок.
6. `feat: implement registration and authentication` — регистрация со всеми проверками приложения В, вход, выход, сессия, роли.
7. `feat: add user cabinet and request management` — избранное, обращения пользователя, обработка обращений администратором.
8. `feat: complete accessibility and responsive behavior` — проверка всех страниц в двух языках и темах, режим для слабовидящих, повторная проверка главной после общих изменений, функциональные проверки.
9. `docs: finalize coursework and deployment` — публичная рабочая версия, инструкция запуска, результаты проверок, записка, графическая часть и сценарий защиты.

Записку, схемы и материалы проверок пополнять на каждом этапе. Не переносить всё оформление на последний коммит.

## Объём продукта и материалов

- Восемь страниц исходного сайта, регистрация, вход, личный кабинет, страница администратора, соглашение, 404.
- Пользователь: избранное, отправка и просмотр собственных обращений. Администратор: просмотр всех обращений и изменение статуса.
- HTML5, CSS/SCSS, JavaScript-модули, Fetch API, JSON Server; без JS/CSS-фреймворков.
- Не менее 10 тестовых пользователей, 30 объектов, по 5 избранных объектов у минимум 3 пользователей; обращения разных статусов.
- Русский и английский языки, светлая и тёмная темы, режим для слабовидящих на всех страницах.
- GitHub Pages для статического сайта и отдельный доступный HTTPS API с сохранением данных. JSON Server — учебный API; реальное разграничение прав требует серверных проверок.
- Записка: ориентир от 35 страниц без приложений; не менее 15 источников со ссылками в тексте; не менее трёх листов А1; исходный `.fig` и графические ресурсы; электронная и печатная записка по методичке; доклад до 10 минут.
